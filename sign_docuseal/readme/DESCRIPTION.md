[DocuSeal](https://www.docuseal.com/) is an open-source electronic signature
platform that can be self-hosted. This module connects Odoo to a DocuSeal
instance: Odoo sends documents out for signature, and follows their whole
life cycle without anyone having to open the DocuSeal back office.

### What it does

- **Sends** a document for signature, either from a DocuSeal template or from
  HTML rendered by Odoo (a QWeb report, typically).
- **Tracks** the request in a `docuseal.submission` record with one
  `docuseal.submitter` line per signer, each carrying its own status
  (*awaiting*, *sent*, *opened*, *completed*, *declined*).
- **Receives** DocuSeal events through an authenticated webhook and moves the
  record along. Handling is idempotent, because DocuSeal retries.
- **Stores** the signed PDF and the audit trail as attachments once every
  signer is done.
- **Reconciles** by cron: a submission still pending after an hour is checked
  against the DocuSeal API, so a webhook lost in transit does not leave a
  request stuck forever.

### Signers stay inside Odoo

Each signer receives a link to an Odoo page,
`/docuseal/sign/<submitter>/<token>`, which embeds the DocuSeal form in an
iframe. The token is generated by Odoo, one `uuid4` per signer, and is
compared in constant time.

This matters for two reasons: the signer never leaves the domain they already
trust, and the DocuSeal slug — which is itself a signing credential — is never
put in an email. Signers do not need a DocuSeal account, and the instance can
stay on a private network as long as the browser can reach it.

### Relationship with `sign_oca`

This module is **not** built on `sign_oca` and does not depend on it. The two
solve different problems and can be installed side by side.

`sign_oca` signs documents inside Odoo: you place the fields on the PDF with
its own editor, and Odoo produces the signature and the certificate. This
module hands the document to DocuSeal, which owns the field placement, the
signing ceremony and the audit trail. Mapping one onto the other would mean
inventing an abstraction that fits neither: the field model, the signer
roles and the certificate are all defined by the external service.

### Requires a paid DocuSeal plan

Two entry points call endpoints that only the paid DocuSeal tiers expose, and
answer `404` on a community instance:

- `create_submission_from_html()` uses `POST /api/submissions/html`
- `create_template_from_pdf()` uses `POST /api/templates/pdf`

Everything else — submissions from an existing template, status tracking, the
webhook, document download — works against a community instance.
